# Dataset Cube M0

Дата: 2026-06-11.

Каталог содержит переиспользуемые CSV для зрелости `M0` в координатном кубе датасетов.

`M0` означает маленький технический или диагностический набор. Его нельзя использовать для сильных выводов о качестве.

## Файлы

- `m0_coordinates.csv`: все координаты `class x scenario x M0` и состояние данных.
- `m0_seed_pairs.csv`: пул seed-пар или report-backed записей пар.
- `m0_canonical_pairs.csv`: плоский вход для канонических M0-запусков.
- `m0_seed_apps.csv`: seed-приложения и app-only записи.
- `m0_source_refs.csv`: ссылки на источники и ограничения.
- `m0_controlled_materialization.csv`: локально сгенерированные контролируемые M0 APK-пары, их SHA-256 и проверки.
- `m0_controlled_materialization.md`: пояснение к локальной материализации.
- `../dataset_cube_status.csv`: единственная рабочая таблица состояния куба.
- `../dataset_cube_status.md`: короткая человекочитаемая сводка состояния куба.
- `DC-C01-S01-M0/manifest.csv`: 7 готовых `repack`-пар как материализованный пул и кандидат на M1.
- `DC-C05-S01-M0/manifest.csv`: готовые `piggybacking`-пары как материализованный пул для C05.
- `DC-C05-S01-M0/materialization_status.csv`: состояние скачивания, декомпиляции и извлечения признаков по `piggybacking`-парам.

## Канонический M0

Для M0-запусков использовать `m0_canonical_pairs.csv`.
Этот файл содержит ровно 2 пары или 2 случая на каждую координату `M0`.

`m0_seed_pairs.csv` является пулом источников, а не фиксированным датасетом для запуска.
Если в пуле больше двух готовых строк, они остаются резервом для M1.

`DC-C01-S01-M0/manifest.csv` и `DC-C05-S01-M0/manifest.csv` сохраняются как материализованные пулы и кандидаты на M1.
Они не задают размер канонического M0.

## Разметка пар

`m0_seed_pairs.csv` хранит не только пару, но и доказательство её класса:

- `ground_truth_kind`: тип источника истины для класса пары.
- `label_source`: источник, из которого взята метка.
- `label_method`: способ получения метки.
- `label_confidence`: сила разметки: `strong`, `medium`, `weak`.
- `evidence_ref`: точная ссылка на строку, отчёт или локальный APK.
- `base_app_id`, `reuse_group`, `independence_unit`: поля для учёта переиспользования одного приложения или семейства.
- `claim_scope`: какие выводы разрешено делать по этой строке.

Для экспериментов, где нужна достоверная разметка класса, использовать только `label_confidence=strong`, либо отдельно обосновывать `medium`.
Строки `weak` нельзя использовать как источник истины для оценки качества метода; они годятся только для планирования, проверки формата или повторного чтения отчёта.
При подсчёте наблюдений в `M0` нельзя считать строки независимыми без группировки по `independence_unit`.

## Усиление слабых классов

На 2026-06-11 минимальная зрелость `M0` закрыта для всех классов: для слабых зон добавлены контролируемые локальные APK-пары.

Дальнейшая работа по переходу к `M1` ведется только через `../dataset_cube_status.csv`.
Для `M1` нужны готовые положительные пары, отрицательные пары, разбиение и теги объяснений.

Локальные APK из `m0/generated-apks/` не коммитятся.
Если они удалены, нужно заново запустить `python3 experiments/datasets/tools/materialize_m0_controlled_apks.py`, затем `python3 experiments/datasets/tools/build_dataset_cube_m0.py`.

## Правило использования

Будущий эксперимент обязан выбрать координату из `m0_coordinates.csv`.
Если эксперимент имеет зрелость `M0`, входные строки нужно брать из `m0_canonical_pairs.csv`.

Строки `runnable_local` можно использовать для технических M0-прогонов.
Строки `stable_cache_decode_verified` можно использовать для технических M0-прогонов при доступном внешнем APK-кэше.
Строки `sha_and_tmp_decode_verified` требуют стабильного APK-кэша или повторной материализации перед воспроизводимым прогоном.
Строки `source_backed_sha_only` требуют сначала материализовать APK.
Строки `report_backed` пригодны для планирования и повторного чтения отчёта, но это не набор APK для запуска.
Строки `needs_seed` нельзя использовать в экспериментах.
